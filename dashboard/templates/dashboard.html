8 Cleaning Steps Applied
Rename columns to clear names

Account→Sender Account, Account.1→Receiver Account, From/To Bank→Sender/Receiver Bank ID.

Parse Timestamp, extract time features

Hour, Day, DayOfWeek, IsWeekend pulled from the raw "2022/09/01 00:20" string.

Drop duplicate rows

9 exact duplicates found and removed — dataset otherwise had zero missing values.

Flag cross-bank & self-transfers

4,387,008 transactions (86.4%) cross banks; 591,212 (11.6%) are same-account self-transfers — both classic AML signals.

Encode categoricals — deliberately mixed strategy

Payment Format (7 values, no order) → one-hot encoded. Currencies → label encoded, which is safe for XGBoost's tree splits but would mislead a linear model. Accounts (515K+ unique) → label encoded only, never one-hot.

Flag currency mismatch

72,166 transactions (1.4%) pay in one currency and receive in another — a classic layering technique.

Four independent outlier-detection methods

IQR (17.36% flagged), Z-score > 3 (0.02%), account-level ratio — 5× a sender's own median (15.17%), and transaction velocity — 10+ txns/hour (732,311 accounts). Combined into outlier_score (0–4) and a master is_outlier flag.

Save final 32-column cleaned dataset

5,177 fraud rows, 5,073,159 normal rows, zero missing values — ready for EDA and feature engineering.

Key EDA Findings
  • Extreme class imbalance — 5,073,159 normal vs 5,177 fraud (0.102%), a 979:1 ratio. Every downstream model, metric and threshold choice is shaped by this.
  • ACH dominates fraud — 0.746% fraud rate vs 0.017–0.038% for Cheque/Credit Card/Cash/Bitcoin, and effectively 0% for Reinvestment and Wire.
  • Amounts are heavily right-skewed — fraud mean $36.1M vs normal mean $4.5M, but fraud median ($8,667) is actually higher than normal median ($1,411), while normal transactions include the extreme long tail (max $1.05 trillion) — motivating the log transform in preprocessing.
  • Cross-bank transfers are 7.8× riskier — 0.116% fraud rate vs 0.015% for same-bank transfers. Self-transfers are the opposite signal: only 0.002% fraud vs 0.115% for transfers between different accounts.
  • Sunday is the riskiest day — 0.311% fraud, roughly 3× the weekly average (0.132% Mon, 0.132% Tue, 0.117% Wed, 0.056% Thu, 0.067% Fri, 0.204% Sat).
  • Weak individual correlations — the single strongest linear correlate of fraud is Day at only 0.019; no engineered flag alone separates fraud, reinforcing the case for ensemble / non-linear models.

Six Feature Families
Velocity
Transactions per sender per hour/day, unique receivers per day. Fraud accounts average 1,364 txns/day vs 953 for normal — launderers move fast.
Amount ratio
Each transaction vs. that specific account's own mean/median/z-score — personalised detection instead of one global threshold.
Structuring
Round-number flags and just-below-reporting-threshold detection — catches "smurfing" (splitting large amounts to dodge reporting limits).
Network
Unique senders-to-receiver / receivers-from-sender, first-time-transfer flag. Fraud receivers get money from 6.5 unique senders vs 3.8 for normal.
Time pattern
Night / early-morning flags, deviation from an account's usual hour. Counter-intuitively fraud is less nocturnal than normal traffic here (20.7% vs 35.3%).
Mule detection
Fan-in/fan-out ratio, composite mule score (0–4). Accounts scoring 4/4 hit a 50% fraud rate — the single strongest engineered signal in the dataset.
Composite Risk Score vs Fraud Rate
Score is a simple sum of 17 binary suspicion flags (outliers, velocity, structuring, network, mule signals). Fraud rate rises from 0.05% at score 0 to 0.32% at score 9 — noisy but directionally real, which is why it becomes one leg of the final ensemble in the Risk Scoring Engine.

Pipeline Steps
Log-transform skewed amounts

Amount Paid / Received → log1p. Raw max was $1.05 trillion against a $1,415 median — log compresses that gap for every model downstream.

Drop low-signal features

6 features with |correlation| < 0.001 removed: is_amount_outlier_zscore, is_high_velocity, Payment/Receiving_Currency_Encoded, Sender Bank ID, amount_vs_account_median. 31 → 25 features.

Stratified 80/20 train/test split

4,062,668 train rows (4,142 fraud) / 1,015,668 test rows (1,035 fraud) — stratify=y guarantees both sets keep the 0.102% fraud ratio.

RobustScaler — fit on train only

Uses median/IQR instead of mean/std, so the $1.05T outlier transaction can't distort the scale. Fit exclusively on training data to prevent leakage; test data is only .transform()'d.

SMOTE on training data only

Plain SMOTE (not SMOTETomek — too slow at 5M rows) with sampling_strategy=0.3: fraud rises from 4,142 to 1,217,557 synthetic + real rows, a 979:1 → 3.33:1 ratio. Test set stays 100% real and untouched.

Bugs found and fixed in this notebook. Four defects were corrected after this run, so these numbers will change once the notebook is re-run: (1) the feature list used column names that don't exist, so a silent "keep only existing columns" filter dropped every amount feature — the CNN was trained blind to transaction value; (2) nn.BCELoss() takes no pos_weight, so the 828:1 class weight was computed, printed and silently discarded; (3) the scaler was fitted on the full dataset and sequences were split randomly, leaking overlapping windows between train and test; (4) the saved score file paired test-set scores with the wrong accounts and zero-padded ~80% of rows.
Architecture
Why 3 parallel branches?

  • Branch k=7 — detects 7-transaction longer patterns

Loading model verdict…
The root cause was a double sigmoid — now fixed. forward() ended in self.sigmoid(self.fc2(out)) while the loss was nn.BCEWithLogitsLoss, which applies a sigmoid of its own. Sigmoiding twice squashed every output into (0.5, 0.731), leaving a near-flat loss surface — which is why training loss sat at ~119 every epoch and every sequence scored exactly 0.731059, the value of sigmoid(1.0). The model now returns raw logits. A duplicated fit_transform that scaled the data twice, and a random split that leaked overlapping windows, were fixed at the same time. Re-run the notebook to replace the figures above.

Key Structural Findings
  • Degree asymmetry is the strongest single graph signal — fraud accounts average an in-degree of 6.54 vs 3.83 for normal, and total degree 1,005.5 vs 704.3.
  • Circular flows carry 4.8× the fraud rate — 0.485% fraud in the 40,402 transactions touching a detected cycle, vs 0.102% overall. 519 of the 812 cycles are simple 2-hop loops.
  • Suspicious communities run 14× hotter — the 62,212 transactions inside flagged communities show a 1.41% fraud rate against the dataset baseline of 0.102%.
  • Graph mule score is highly predictive at the extreme — accounts flagged by all 4 graph mule criteria (score 4) hit a 3.64% fraud rate, 36× the baseline, though only 165 accounts reach that score.
  • Fan patterns split cleanly — "Collector" (fan-in) accounts run 0.168% fraud, "Mule" (both fan-in and fan-out) accounts run 0.196%, both above the 0.100% "Normal" pattern baseline.

Why this happens. The weights below are not a design choice — the engine automatically redistributes weight away from any model with no full-coverage scores, and at build time only XGBoost and CNN-1D had them. That handed CNN-1D 14.7% of the blend despite an AUC-ROC of 0.5172 (near-random, see its tab). Mixing a random signal into a good ranking shuffles it, which is why ensemble AUC-ROC (0.7039) sits far below XGBoost-alone (0.9110), and why the alert queue captures so much less fraud than the same number of alerts picked by XGBoost alone. The fix is to rebuild the ensemble with CNN and LSTM at 0% weight — the composite rule-score can stay, but the blend should not include a model that cannot separate the classes.
